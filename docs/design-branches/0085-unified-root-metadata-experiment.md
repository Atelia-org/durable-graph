# DB-085：统一根目录与轮转实验

> 2026-09-30，已完成并通过独立 Astra 只读验收；本片停点无阻塞。依据[本片范围](0085-unified-root-metadata-next.md)及用户本轮授权。只改隔离实验和必要观察接缝，不改变产品公开 Open/writer/Audit/rescue；实际改盘仅新建独立夹具。

## 问题与共同故事

保留已有分支 A；追加事件并创建 B，此次数据写入从首段轮转到第二段；随后更新 B，A 的身份、head 和旧地址保持。原路线使用真实 EventJournal，候选复用相同 EventFrame、RefId/Create 分配及分段地址语义，以根固定完整目录和段视图。双方不执行 DG 图/Schema 管线；不能据此报告产品速度倍率。

候选的 RefId 使用实验 `allocation.rbf` 的 Create 帧 ticket，是独立身份域；它复用真实 codec 和身份分配原则，不宣称能由旧 EventJournal 的 ref-op-log 直接解析，也不是产品格式兼容层。

源码对照：`Repository.Publish` 先 Schema/State，再 Journal，最后 branch ref；仅 `Fork` 不追加数据，不能用来证明本片轮转。`EventJournal.CreateBranch` 先确认目标段，再 Create → ref 对象 Init → BindName；catalog checkpoint 另有完整快照替换协议。`RbfSegmentStore.RotateActiveSegment` 则是旧段 flush → 新段创建/flush → locator 临时文件 flush/替换 → 交接；第二段存在而 locator 仍指首段时，普通 Open 返回 `NextSegmentPresent`。这些是本片要对照的发布/恢复状态，不从单分支共同提交点推断缺陷。

| 显式实验恢复与续写 | 连续物理前缀、所有完整事实含 orphan、确定的身份高水位 | 从盘重推，不执行锁外报告 | 同锁资格 → 关闭候选 → 复核 → 最多一个合格尾动作/屏障 → 全新资格和依赖/根确认 | 动作、确认、交付前可再次中断；重试保持全部完整字节和地址 | Trailer 1–11B、完整矛盾、未知文件、检查未完成不授予动作资格 | 统一业务选择；物理尾、身份分配和名字持久责任仍存在 |

段创建的新窗口：尚未被任何完整根引用、仅有匹配 RBF Header 的 0–3B 第二段，可以作为明确的“完成初始化 Header”实验动作；它不截断完整事实、不复用完整帧身份。只允许已知第二段且全库资格成立，已有字节必须精确匹配；该动作和再次中断单独验证。其他短尾继续沿用连续前缀资格，不能借此补全 Trailer 1–11B。若实现无法充分证明该资格，明确拒绝并报告，不隐藏为普通成功。

普通随机读取沿用已批准的受控 writer 来源前提：固定根槽、CRC、格式、所选依赖和 EOF 检查，不独立证明任意伪造 ticket 的物理成员资格。恢复资格必须从连续物理前缀建立成员及 EOF 边界集合；opaque payload 内嵌合法帧不能取得动作资格。两类证据不得互相代替。

本机执行明确标为进程故障 F1：内容 DurableFlush 是实际调用；新文件名仅有进程存续可见性，没有实现的平台目录屏障不能记为成功。需要断电保证的模式必须拒绝，不能用 no-op 放行；F2 图像模型独立展示缺名字、缺依赖、旧范围损坏和未确认根风险。

## 证据与停点

真实写 hook 和外部 Kill 覆盖新段、目录、根、回包及恢复再中断。故障注入、图像模型分别记录。完整前缀 hash/地址、A 保持、B 发布状态、重试续写、独立冷开为通过标准。

完整成本包含写入准入、全部屏障、追加/目录字节、Open+首次读取、恢复和残留文件数；分别改变历史、失败残留和无关分支数量。请求/返回/预取、线程分配与未覆盖的元数据 I/O 分列，进程冷开不等于 OS cache 冷。原路线尚无相同范围的恢复实现，缺口明确列出，不制造恢复性能倍率。

主线程 Astra high 负责合同与整合，Sol xhigh 实施明确工作包；独立 Astra 只读验收的线程限制处理见下文。所有 .NET 串行 Release，源码联调和任务专用 C: TEMP/TMP，保留 ShouldUnsetParentConfigurationAndPlatform=false。停在证据与路线建议，不自动实施产品格式迁移。

## 实际实现与发布权威

实现与运行入口见 [UnifiedRootProbe](../../experiments/UnifiedRootProbe/README.md)。原固定双值命令保留，新命令为 `metadata-*` 和 `baseline-*`。

- 候选持有独占 `repository.lock`，使用 `allocation.rbf`、`catalog.rbf`、`roots.rbf`、`events/segments/00000001.rbf`；创建 B 的真实写入才建立 `00000002.rbf`。不生成独立 ref 对象、`active.segment` 或 `catalog.snapshot`。新段采用后不每次失败另建段，第三段明确不支持。
- 事件使用真实 `EventFrameHeaderCodec`、32B payload 和 `EventAddress`，物理帧 124B。Create 使用真实 `RefOpFrameCodec`，其 ticket 成为实验域 RefId。序号取全部完整事件的物理高水位，不按逻辑 head 重用；重试会越过完整 orphan 新增事件和身份。
- 根物理槽固定 76B，保存 generation、目录 ticket/EOF、allocation EOF；目录是一个完整、按名字排序的版本，含每个名字的 RefId/head、active 段号及两段 EOF。旧根不借最新 locator/ref 解释旧 head。
- 创建 B 的完整入口包括全量资格、旧依赖和旧根重新确认、第二段创建/确认、事件、Create、目录及根的依赖先行屏障。最后根 flush 成功才返回。每次计量的 CreateB 为 9 次内容 flush；不能只数末尾 root flush。完整未回包根仍是新视图，不能因调用者未知而删除。
- 恢复在同一次锁内扫描所有连续物理前缀，验证全部完整事件/身份/目录/root，包括 orphan；所有候选 reader 关闭后，再次全量资格与边界复核，才进行一个合格短尾截断或第二段 Header 补齐。之后全新资格并按段、身份、目录、根的顺序重新确认，关闭资源后返回纯数据报告。无动作也有 5 次确认；有动作另加一次屏障。
- Header 补齐只接受未被任何完整根或完整依赖引用、匹配 `RBF1` 的新第二段 0–3B。已有前缀复核后只补缺失字节；截尾仍须完整连续前缀和所有保留依赖资格。Trailer 1–11B 不顺带补全。

普通 Open 使用固定槽定位根，并读取一个所选完整目录；首次 `ReadAll` 校验所有分支身份/head 与各自完整 Parent 闭包。**有短 root 尾时另有例外**：即使显式请求历史 generation，也先验证最新候选目录及其依赖来判断根短尾，然后读取所选旧目录。旧根返回值和子视图 EOF 固定，不代表这条异常路径从不读取后来的候选元数据；CLI 的计量说明已注明。当前 reader 反复新开固定 EOF 文件并重复检查共享祖先，未做操作内复用。

预算仅覆盖首次资格的物理扫描与语义读取请求，包括直接读取重试；动作前重新资格、最终资格与确认不受此预算限制。目录枚举、路径/长度/属性查询、CPU、内存也不受该字节预算约束。计量覆盖整个调用，故没有把这些额外扫描从成本中扣除。

### 已减少与新增的规则

| 责任 | 原 EventJournal 路线 | 本片候选 |
|---|---|---|
| 名字绑定与 head 发布 | Create → ref Init → BindName；更新另有 ref Advance | Create 仅分配身份，目录候选不发布；唯一 root 同时选择名字/身份/head |
| 目录 checkpoint | `catalog.snapshot` 原子替换与 ref-op 后缀重放相互配合 | 不发布覆盖式 snapshot；每次保存一个完整不可变目录，由 root 选择 |
| 活动段发布 | 旧段 flush → 新段/flush → locator 临时文件 flush/替换 | 段文件只是物理事实；root 选择已发布段视图，资格确认后可以复用未发布第二段 |
| 失败后的业务选择 | 要组合 locator、catalog、ref 的各自状态；本片未实现旧 S1 救援 | 由一个 root 选择；仍须处理真实短尾、身份高水位与残留段 |
| 新增负担 | 当前单分支 ref 本身已是最后提交点 | 完整目录历史、固定根日志、所有目录的跨版本资格、Header 初始化残留，以及完整目录复制/读取成本 |

这不是给旧发布链末尾加日志。它确实替代候选中的发布权威，但没有删除物理恢复、目录项持久性或全部校验责任，也没有证明真实 DG 图/Schema 已完成适配。

## 验证与独立验收

全 Release、源码联调、任务专用 C: TEMP/TMP、串行 .NET。

- 根 solution 构建成功，0 警告/错误；Persistence 1,152/1,152 回归通过。最终实验构建 0 警告/错误；metadata 25 组自测、既有固定双值 15 组自测通过。
- 候选最终机制版本重跑 36 个案例、39 次真正外部 Kill：Header 0–3B、各文件实际短写/完整写/flush、目录/root/回包、B 更新，并含 Header 写后屏障前、截断后屏障前及报告前再次终止。每例恢复后立即独立读，再正常续写、独立进程冷开和旧根复读。没有用 Dispose、异常展开或裁剪图像代替这些 Kill。
- 原路线另有 16 个真实中断案例：13 个创建/轮转/checkpoint 窗口和 3 个 B Advance 窗口。新第二段存在但 locator 仍旧的四个窗口明确报 `NextSegmentPresent`；locator 发布后可重开，B 是否可见由 ref 发布决定。用 A 加 511 个无关分支触发真实 catalog checkpoint，替换前后均保留 A 且 B 尚未绑定。未实现旧 S1 恢复，因此其恢复成本是 N/A。
- 独立验收重算修复后候选 327 份子进程日志、39 个 READY/PID Kill、688 组完整前缀 SHA 和 969 个物理 offset，全部吻合。原完整矩阵的 52 案例、55 次 Kill、3,876 组 prefix 和 10,338 个 offset 也已独立重算；它作为修复前正例及未变的原路线证据保留，不替代修复后的候选验证。
- F2 仅是显式图像模型及屏障顺序注入：缺文件名、丢依赖、旧范围受损拒绝；可读但未 flush 的根可在模型中消失。`PowerLossRequired` 在改盘前拒绝；没有平台断电保证。成本动作夹具由真实 2B Write 后异常展开产生，只用于成本准备，另由上述真实 Kill 证明中止闭环。

独立审查发现并推动修复了两种完整 orphan 目录漏洞：root0 后出现 generation=99 的完整目录；以及下一代目录将 B head 退回已发布前代。现对每个完整目录依据物理位置确定合法发布代数，并与其已发布前代 root 对照身份、head 和 EOF 前进关系；同代多个失败候选允许共存，但不能跨代或回退。两个反例分别叠加 Header0/根短尾，均在动作前拒绝，原文件逐字节不变。F1 顺序测试另按 offset 区分新段 Header 写与事件写，避免把 Header flush 当作事件屏障证据。

审阅结论：本片停点通过，没有剩余阻塞。工具拒绝创建额外线程后，复用了未参与本片实现的独立 Astra 审阅线程；其判断基于本片合同、源码和原始证据，没有重读旧评审或沿用旧结论。

双方责任并不完全相同：候选每次 writer 和恢复都全量资格，原路线按需加载端点；候选 ReadAll 对每个分支重复校验 Parent 闭包，基线复用现有 EventJournal reader 和 A/B 祖先查询。表格反映各自真实行为，不给路线速度倍率。长祖先格中候选首读明显较重，不能以“以后可优化”从当前成绩中扣除；源码可定位重复开 reader 和共享祖先重读，但优化幅度尚未验证。

全部测量未控制 OS/device cache；独立进程不等于冷页缓存，返回字节不等于设备 I/O，线程分配不等于峰值/驻留内存。样本数小，不报告显著性。完整原始 RBF/direct、请求/返回、raw、预取、flush、分配、文件数与每个样本在成本报告中保留。

## 路线建议与停点

**继续把统一根作为优先候选，但不据此批准产品迁移。** 它在真实 Create/ref/段语义中减少了独立发布权威，并能保留失败残留、从同一旧根继续；这是比固定双值实验更强的正面证据。代价是完整目录复制、历史目录资格和当前 reader 的重复工作，writer/恢复全扫问题仍在。

下一项决定性证据应是将真实 DG 的 Schema、State、Journal 所需版本与地址映射到这一发布模型，在有代表性的目录规模下比较一次真实图提交、重开和首次图读。先核对所需接缝、保留依赖与完整成本，再裁决是否替换产品协议；不先建通用 CoW map、Clean 或任意事务框架，也不预先铺开新的长期分片。

本片没有验证 tag、删除/归档、根日志自身轮转、多个数据 store 同时轮转、Schema/对象身份分配、真实 DG 图恢复、快速 writer/快恢复或选定 OS/FS/SSD 的断电保证。普通 Open/writer/Audit/rescue 保持。改动留在 working tree，未提交、发布或迁移真实数据。

两仓起点 dirty 文件逐项 hash 核对，没有丢失既有文件。已有文件的本轮增量仅为实验 Program/project/README、活动文档与导航，以及上游 EventJournal/SegmentStore 为实验程序集增加的 internal 访问声明；既有产品源码和测试改动保持。474 个受影响文档本地链接路径有效，文档保持 LF，两仓 diff 空白检查通过；文档收口后最终 25 项源/二进制 hash 未变。
