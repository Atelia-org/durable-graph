# DB-104 · 通用 TextEditor 与 DurableGraph 的集成边界

目标是让同一套 LLM 工具编辑内存草稿、当前世界的 memo 字段和文件。第一片推荐把现有编辑器搬到 `Atelia.Text.TextEditor`，让它记住文本相对于最近一次已接受基线的来源范围，由 DurableGraph 针对本图的准确前驱生成载荷。本轮已建立[独立程序集与测试项目](../../text/README.md)，结论来自隔离原型；主线领域类型仍是 `DurableText`。[对照数据与复现](evidence.md) · [现行保存合同](../0101-durable-text/README.md) · [现行查询与编辑合同](../0103-durable-text-search/README.md)

## 总体方向

- 在本仓建立独立的 `Atelia.Text` 程序集与测试项目。编辑器拥有内存正文、快照、串行编辑和同步全文访问，消费方只需引用文本包即可使用内存草稿。
- DurableGraph 引用文本库，识别领域字段里的编辑器，负责对象图身份、准确持久前驱、Base/Delta 编码与发布。文件和内存由各自的宿主定位与管理；同一份内存正文可以成为图字段，也可以导出到文件。
- 后续在公共文本层研究单篇字面及正则 Search、ReplaceUnique、ReplaceAll。工具宿主管理地址、可见集合、调用顺序和保存回执；多行原始输入与结构化输入可以调用同一操作。批量替换预览与跨回合确认留待第二片的工具实验。[既有用户故事](../0103-durable-text-search/README.md#memo-编辑工具与批量替换预览)

第二片可让模型先用 `text_search` 查找，再把命中回执中的地址传给 `text_replace_unique`。用 `mem:draft`、`memo:entry-42/FullText`、`file:notes/today.md` 试验同一地址参数；具体语法由工具实验决定。宿主用 Atelia.Completion 的 `MethodToolWrapper` 包装结构化参数，在支持原始文本的适配器上用 `TextToolWrapper` 比较多行编辑体验。回执区分工作副本已修改、图已提交和文件已写回。

## 第一片的设计问题

同一处局部改写，编辑器已知道留下的字来自哪里，写入端则知道本次允许依赖哪一版。两份知识放在哪里，会影响普通编辑的内存占用、保存时的扫描、Delta 大小与冷重开成本。我们分别比较了来源算法与接口可见性。

| 来源放在哪里 | 有利工况 | 代价与取舍 |
|---|---|---|
| **编辑器保存一份基线身份，每片带来源偏移；DG 提供准确前驱** | 先保存、整理片表、再改多处，甚至物理字符串已全部更换，仍能直接给出多个 Copy。冷开恢复也能立即续写。 | 每个编辑器最多跟踪一份来源。多图交替接受同一实例后，若前驱身份不合且内容有变，DG 安全地编码全 New。x64 实测每个片数组槽 24 B，删去来源偏移的对照片为 16 B。选作首片。 |
| DG 比对前后两份快照，以不可变字符串身份和物理区间推导 Copy，前后缀相等作补充 | 不需要每片存基线偏移；多图交替写同一对象并仍共享底串时，能在任一准确前驱上重新发现 Copy。 | 基线被压平后，同版的物理表示也可能完全不同。可让 DG 为每图另留一份压平后的映射，换取更多驻留；也可引入内容匹配，增加保存时的扫描与匹配预算。交错多图写成为实际常见负载时重访。 |
| DG 只看完整内容，比较最长公共前后缀，或直接写新全文 | 单次局部编辑可恢复紧凑的三段；实现短，容易与字符串 oracle 核对。 | 两处相隔很远的改写会把中间未变的文字也作为新字面写入。适合作对照和无法证明来源时的回退。 |
| DG 按编辑通知维护每图日志 | 同一个实例可同时跟踪多个前驱。 | 每次编辑要被观察，纯内存对象入图前仍需建基线，跨图还要定义订阅寿命、压缩、重入与失败的原子性。当前没有需要付这笔编辑侧成本的消费者。此路线只作设计分析。 |

**跨程序集选窄的内部操作，产品友元只给 `Atelia.DurableGraph`。** 直接让 DG 操作 `TextPieceView` 和可变列表最省搬迁工作，但会让 codec 知道片表如何定位、合片以及何时失效。把相同操作公开为中立 checkpoint API 也能实现同样的性能，却要求独立文本包的用户理解并长期依赖一套来源与安装协议。等第二个实际消费者也需要准确范围增量时，再据其调用方式提取公共合同。文件适配器只需读写正文。IVT 实际授予整个程序集访问权限，窄边界靠生产调用点和测试维持。

## 第一片的协作合同

以下名字表达内部操作，供实施时收敛。公共 `TextEditor` 保持引用身份和串行使用约定，快照、范围编辑、查找和全文访问沿用 DB-103。

| 时机 | 文本库提供 | DG 负责 |
|---|---|---|
| 捕获 | 冻结不可变内容及其来源，提供 O(1) 长度与片数、准确的非空分段、内容相等比较。冻结结果可独立于编辑器存活。 | 同一图中，指向同一编辑器实例的字段和容器元素共享 ObjectId。内容相同的独立实例各有自己的 ObjectId。冻结时保留分段，估算 Base 成本，在选定 Base 后才编码。 |
| 准备 Delta | `current.TryGetSourcePlanFrom(previous, out plan)` 将来源与该前驱的内容身份核对。计划是只读的索引视图，逐片返回 Copy 范围或字面切片。 | 先处理同版或改回原文的 NoChange；有准确来源时顺序合并并编码，来源不合时写全 New。计划只在这一次前驱/候选配对中消费。等长内容比较可能扫描全文。 |
| 为 State 准备安装 | 事先准备同版的新物理视图与不透明安装凭据。凭据持有编辑器和捕获的物理视图，仅保存候选在短期内持有它。 | 准备期把这批凭据从捕获上下文交给保存候选。State 发布并接受图之后，调用 DG Runtime 内部的批安装操作；逐项核对编辑器及捕获视图后交换引用。此阶段不分配、不回调用户。丢弃或中止时释放整批，独立 Event 不准备这批操作。 |
| 冷读、恢复与续写 | 独占的内部构造器允许从前驱借准确的物理字符串切片、追加新字面、冻结一次。借用不保活整份前驱视图。恢复到新编辑器时以恢复内容建立基线。 | DG 先完整校验 Delta 和前驱范围，再重组。超过现行 4096 物理片预算，弃掉整份局部结果，从该记录起点重读并平坦构造；只在整链结尾检查滞留大底串。Base 保留按声明长度直写最终字符串的路径。 |

有三个容易混用的身份。公开条件编辑检查**编辑器归属和内容版本**，同版物理重绑后仍可用。安装凭据检查**捕获的物理视图**，捕获后的编辑或物理整理不能被旧凭据覆盖。产生 Copy 计划时检查**本次前驱的内容身份**，由 DG 负责选出准确的持久对象版本并把 Delta 系到该记录。若替换成另一份等长前驱，回放时所有范围校验都可能通过却读出错误的字。保存成功才允许把新发布的整篇作为后续 Copy 基线。两个独立恢复的编辑器拥有不同的公开快照归属。[现行编辑与安装](../../../src/DurableGraph/DurableText.cs) · [图发布后安装](../../../src/DurableGraph.Persistence/BusinessWorkspace.cs) · [冻结上下文的释放](../../../src/DurableGraph/Runtime/Capture/CaptureSession.cs)

## 长期无保存的正文

纯内存草稿也需要整理时机。推荐先在明确的编辑批边界试验按需整理，保留同一编辑器与内容版本，已经发出的快照继续可读。默认整理频率用真实草稿轨迹决定。首次图保存之前的领域字段也可能没有来源基线，单凭空的来源 token 无法区分它和内存草稿；在每次普通编辑后自动压平会改变首次图 Base 的分段与成本。

未跟踪前驱时可安全地压成一个 New 片。已有基线时，首片继续用成功保存后的既有整理路径。若需在两次保存之间释放底串，可给活片共用一个新底串，并按原 Copy/New 来源切片；只有兼容的相邻来源才可合并。保留来源可能仍需多片。旧快照或调用方继续引用旧底串时，其内存会在这些引用释放后才可回收。[碎片、来源和驻留见证](evidence.md#无保存编辑)

## 实施顺序与验收

1. 搬移编辑器、快照、编辑值、片表与现有读写算法，在文本包上运行 DB-103 合同和纯内存的长编辑轨迹。用一个普通 net10.0 消费者仅引用 `Atelia.Text`，验证查询、编辑、嵌套访问和快照条件提交。
2. 在 DG Runtime 接入上述热写、冷读和准备安装操作，Persistence 保留图级接受时机。跑同版重绑、捕获后编辑、丢弃/发布失败、独立 Event、跨图共享与净零变化回归。[现有集成反例](../../../tests/DurableGraph.Persistence.Tests/DurableTextIntegrationTests.cs)
3. 生成器按新程序集与元数据类型识别，更新当前和迁移目标的对象绑定、值投影、泛型/容器的 CLR 反向解析及包导出清单。用独立普通 DG 包消费者让同一编辑器出现在两个字段，实际保存、关闭、重开、在中间改一个字再保存。检查领域别名、对象 ID、记录类型、准确前驱、Copy / New / Copy 的范围和再次冷读的正文；验证结构 Schema 的既有 golden 与同名伪类型拒绝。新 API 允许直接替换旧源码类型。

这一轮已建立的文本包可独立打包和加载，导出零个公共类型；新编辑器、DG 原生绑定和第二片工具进入各自的实施与验收阶段。
