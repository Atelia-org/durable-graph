# DB-104 · 通用 TextEditor 与 DurableGraph 的集成边界

希望同一个 LLM 工具可以编辑内存草稿、当前世界的 memo 字段和磁盘文件。本轮先研究其中的公共基础：从现有 `DurableText` 提取一份独立编辑器，让 DurableGraph 原生识别 `Atelia.Text.TextEditor`。现行片表、保存和查询合同分别见 [DB-101](../0101-durable-text/README.md) 和 [DB-103](../0103-durable-text-search/README.md)。

## 总体方向

- 在本仓建立独立的 `Atelia.Text` 程序集与测试项目。编辑器拥有内存正文、快照、串行编辑和同步全文访问，消费方只需引用文本包即可使用内存草稿。
- DurableGraph 引用文本库，识别领域字段里的编辑器，负责对象图身份、准确持久前驱、Base/Delta 编码与发布。文件和内存由各自的宿主定位与管理；同一份内存正文可以成为图字段，也可以导出到文件。
- 后续在公共文本层研究单篇字面及正则 Search、ReplaceUnique、ReplaceAll。工具宿主管理地址、可见集合、调用顺序和保存回执；多行原始输入与结构化输入可以调用同一操作。批量替换预览与跨回合确认留待第二片的工具实验。[既有用户故事](../0103-durable-text-search/README.md#memo-编辑工具与批量替换预览)

## 第一片的设计问题

需要决定片表与来源信息的归属、跨程序集最低限度要交换什么、准备与安装分别由谁触发，以及内存文本何时整理碎片。用同一组见证比较候选：无 DG 的编辑与反复查询；图字段共享身份与冷重开；准确前驱上的局部替换；同一编辑器被不同图保存；捕获后编辑、丢弃准备或保存 Event；同版重绑后的快照条件编辑；长期没有保存的内存草稿。

实施时最小的端到端验收是两个普通包消费程序。一端仅引用文本包即可编辑；另一端在 DG 领域字段上保存、冷重开、修改中间文字再保存，验证实际 Delta 为准确前驱的 Copy / New / Copy。本轮交付总体文档、程序集骨架和候选的可复核比较；当前产品行为仍由现有 DurableText 提供。
