# DB-105 · 第三方容器如何持有图引用

**两种注册方案均在真实 Repository 中恢复了别名和环，且能只写实际改动的对象。** 对于节点私有的有序边序列，声明引用槽可以显著减少作者代码，并保有稀疏 Delta。对于自己有增量算法的私有内容，保留类型提供 Delta 的能力对实际写入量很重要。普通持久字段与 BCL 容器已经能表达共享与循环。主线公共合同见 [DB-104](../0104-text-editor/README.md)，本片的可执行代码保存在本地研究分支 `research/db104-registered-nodes`。

## 三种作者写法

| 做法 | 类型作者提供什么 | 有序引用如何保存 |
|---|---|---|
| A，作者编码 | 冻结值、引用投影和枚举、版本 reader、Base/Delta、分配和回填 | 槽顺序、空位图、变长对象 ID 和稀疏位置补丁由作者定义 |
| B，声明槽 | 一个分配函数、私有值的读写函数、各个有序槽的 getter/setter 及目标类型 | 框架保有冻结槽，统一做 Base、稀疏补丁、历史枚举和回填 |
| 生成模型 | 声明普通持久字段，使用 List 保存有序引用 | List 拥有独立对象身份，由内建容器负责保存和恢复 |

A 和 B 共用一个绑定适配器。捕获时 DG 按实际目标检查声明类型，登记本图的对象 ID。旧 reader 重放 Base/Delta 后，DG 在完整旧目录上检查每个上报的 ID，再允许版本转换。恢复时先创建所有可达实例，再按本次打开的实例目录填回各条边。B 在同一条路径上从槽声明产生访问行为。研究复用了叶登记及无字段名义 Schema，以便两组经过主线生成器、Repository 和现有图恢复器。[主线的历史校验](../../../src/DurableGraph.Persistence/StoredGraphBodies.cs) · [主线的恢复器](../../../src/DurableGraph.Persistence/GraphReader.cs)

作者程序集只直接引用 DG Runtime，使用公开 API，无友元权限。研究载体沿用 `[DurableLeaf]` 与 `RegisterLeaf`，低层节点 codec 新增捕获上下文、带版本的引用访问、分配与回填，三个同步上下文均为 `readonly ref struct`。冷开经过普通 Repository 入口；研究宿主另用只读反射取得对象角色、帧地址和已提交批次，以便逐条查账。交付形态是源码程序集，这一轮没有做 NuGet 打包对照。

两种外部 codec 用同一个公开密封 CLR 类型、各自独立的文件仓。按研究记录中可复算的口径，扣除空行、单行注释、导入和命名空间，A 需要 174 行作者接线，B 需要 19 行，两者另有相同的 6 行节点模型。生成模型本身占 8 行。B 的 3 个通用框架 helper 共 349 行。A 的代码包含作者选择的紧凑编码、规范性检查和稀疏补丁。给 A 多加一个 Bucket 类引用，作者要维护冻结投影、遍历、回填和 wire 两端；B 的同一份访问器与目标类型声明驱动这些操作。

## 身份在哪一层

模型的 A、B 共享 C，C 指回 A。A 的 Bucket 是根实际持有的 List。B 的 Bucket 是一个仅通过 B 可达的 List，内含 C、B、C。改变 C 的私有整数后另起进程冷开，将 B 的一个槽从 C 改向已有的 D。既检查历史图内所有别名，也在同代同时打开两份可独立编辑的图。宽节点用 10,000 个槽，每四个有一个 null，其余重复指向 A 或 C。

一个额外的领域根用 Dictionary 引用两个节点，把同一个数组赋给这两个节点的 Links 和两个普通数组字段，并共享一个 Bucket。冷开后，两个普通字段仍共享那个数组；两个节点各有一份 Links 数组，三个数组里指向的领域对象仍相同。所有 Bucket 则指向同一个 List。向其中一个 Links 数组写入新值只影响该节点。这是扩展作者要向其用户说明的选择：公开可变集合若需要独立身份，应把集合本身登记为一个引用目标。若容器只公开元素语义，可以把槽序列内嵌在自己的记录里。

## 实际选择的 Base、Delta 及写入量

下表中的对象 body 均为字节数。Base 含类型头，Delta 列为记录内的 Delta 正文。批 payload 来自已经提交的 Frame；整仓增长是保存前后全部仓文件逻辑长度差。使用默认 `SaveGraph` 策略。

| 工况 | A 作者编码 | B 声明槽 | 生成模型 + List |
|---|---:|---:|---:|
| 万槽初始，全部对象数 / body 合计 | 7 / 8,800 | 7 / 10,053 | 11 / 10,065 |
| 只改 C 私有整数，仅 C 写 typed Base | 8 | 8 | 6 |
| 8 槽，换中间一个孩子，选中 typed Base | 13 | 15 | 12 |
| 万槽，同样换一个孩子，选中 Delta | 5 | 6 | 10 |
| 上一行对应的整批 payload / 整仓增长 | 51 / 296 | 52 / 296 | 56 / 300 |

A 用位图标记空位，B 和生成对照在重复槽中为每个空位编码零。初始宽节点的四分之一为空，ID 均很小，这解释了 A 的初始大小优势。改边时 A、B 各写 B 节点的一行，生成模型只写 B.Links 的一行。冷读能从该对象的准确前驱重放。B 的原始 6 B 补丁回放仍须复制完整的 10,000 个无符号 ID；单独回放 32 次平均在调用线程分配 40,120 B。这个实验只据帧和字节比较三种表示，单次保存的耗时不用于给方案排序。

另用一个持有自引用的节点隔离私有内容的变化。两路初始 4,096 B 私有块、同一条边、整份 typed Base 逐字节相同。翻转偏移 2,048 的一个字节后，A 用“位置、值”编码，落盘为原始 3 B 的 Delta；含种类、前驱和长度编码的对象 payload 共 17 B。B 能为边做稀疏补丁，当前私有块变化时整块替换，产生 4,099 B 的 Delta 候选。规划器实际选择 typed Base 4,102 B，对象 payload 为 4,105 B。此处的对象 payload 不含批内对象 ID 及整仓文件开销。冷开两代的私有内容和自引用均正确。

## 历史校验的信任边界

用真正的 v1 writer 保存含 string 引用的 Base 和 Delta，再追加两份目录，一份缺少目标，一份将目标替换为同 ID 的错误类型。节点旧记录的地址与字节相同。正确的 A 旧 reader 与 B 的旧槽声明都在分配 v2 节点前拒绝坏目录；正常两代均可读，v2 可以在校验后移除该边。保存端也会在准备 Base 前拒绝作者上报的悬空或错型 ID。

同一坏目录也提供了反例。A 漏报那个已退役的槽，或者 B 的历史描述把它写成采用相同二进制编码的整数，v2 都能交付一个表面正常的对象。这里框架看得到 ID 及当前 reader 对旧版本的解释，现存名义 Schema 没有当年该槽的描述。声明式接口能减少作者遗漏，持久化历史与注册信息之间的可核对证据仍值得单独设计。

## 选型与复现

常规字段和需要独立身份的集合优先用现有生成模型。若私有内容已有叶 codec，生成模型持有叶与普通引用字段也是现成的组合，代价是多一个可独立引用和保存的对象。对于需要内嵌槽的扩展类型，优先研究“DG 按带类型的槽处理出边，作者按需提供私有内容的 Delta”。可先用现有版本化 Schema 或独立持久描述核对历史槽的编号、目标和基数，让上面的错误旧声明得到确定的拒绝。下一次验证可以直接复用本片的 4 KiB 翻转样例与坏历史样例。开放泛型、自定义字典键及物理 Rope 子树地址需要各自的消费者和实验。这里接受的是图机制的可行性，正式公共签名与持久格式仍待决策。

2026-11-20，两份独立运行各建 6 个仓，每个仓由 3 个进程完成首写、冷开续写和三代复核。两次运行的 62 条物理对象记录逐条比对，种类、正文 SHA-256、地址和前驱一致。研究源提交为 `dffa9d0a`，Release 根构建零警告、零错误，五个测试程序集共 3,393 项通过，零跳过。`0be089f6` 收录回执、作者比较，并将私有块测试的初版相等断言加强到完整 typed Base，该版本的 7 项节点专项回归全部通过。从主线检出该提交即可取得全部代码和数据。
