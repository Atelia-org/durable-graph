# 由发布时的 Schema 解释已退役的节点引用槽

## 问题和验收

v1 写入 `Value, Link, Padding`，其中 Link 是指向 string 的单个 ID，Padding 是内嵌的可空 string ID 序列。v2 只保留 Value。作者每个版本只登记当时的槽。用只有 v2 声明的注册表打开 v1 的 Base 和 Delta，健康目录读回 10、21；同一个节点头遇到缺失目标或同 ID 错型目标，必须在分配根、节点或回填之前报错。这是用户选定的可观察目标。

| 约束及来源 | 对实验的含义 |
|---|---|
| 用户决定与 DB-105 的坏目录实测 | 旧边的性质取自 v1 写出的描述；删除边是 v2 的投影规则。保留实际落盘再冷开这一消费边界。 |
| 现有 StoredGraphDecoder 与持久合同 | Base 的源 Schema 解释正文，选中 State 的完整目录供应目标 ID 与类型。使用既有先旧图校验、后规范化、再分配和回填的顺序。完成的帧只追加。 |
| 已有外部消费与原型 | 一个第三方封闭节点，标量、单个引用、内嵌引用序列。当前 B 只支持尾部增删。自包含叶和生成模型已有独立绑定。 |
| 现行运行模型 | 同一次同步打开，历史字节和本地模型处于同一进程可信边界。无需引入跨仓注册服务。旧研究仓没有发布格式兼容要求。 |
| 待检验的选择 | 旧描述如何进入现有 Schema 图、如何区分 B 的正文语法、兼容范围如何表达、历史私有块的哪些规则必须由作者提供。 |

## 待审方案

1. 写入时从 B 当前成员的有序声明产生一个完整的版本化布局。考虑复用现有 `DurableSchema` / catalog 描述符、类型表达式和字段编号。布局至少应能区分整数、单引用和内嵌序列，并保存精确的引用目标约束。需证明读者如何区分相同字段列表但正文/Delta 语法不同的模型。首片比较按位置做尾部删除与另设长期槽 ID 是否值得。
2. 冷开时从准确 Base 源 Schema 绑定只读解释器，按同一个描述重放 Base 及准确前驱 Delta，并枚举最终旧状态的边。继续走现有全目录引用校验。同版注册若与持久描述冲突须拒绝。旧描述不完整时也须有明确结果。
3. 在校验通过后，v2 将共同前缀带入当前冻结状态，舍弃尾部。作者表达接受 v1 并给出当前声明即可。实验不自行推断字段改名、换序和私有格式升级。
4. 专门比较将描述保存在已有 Schema 图、另立历史槽表、以及只存指纹再由 v2 提供 decoder 三条路径。保留能够独立解释旧引用且能区分错型的最小做法。

## 审查后的实验合同

采用一种新增的 Schema 描述符变体标记 B 的正文语法。复用现有 Schema 图、编号及类型表达式；业务 Base 的类型头继续指向描述符，Delta 继续使用准确前驱。每一槽按正文位置保存整数、单引用、内嵌引用序列或有界私有块的种类。前两种的一字节值可以完全相同。内嵌序列逐个检查非零 ID；对数组对象的单引用只检查一个 ID。私有块记录格式名，格式名与领域类型分别解释。描述符身份包括语法和有序槽，空槽列表也必须区分普通 Schema。

当前声明显式列出可直接升级的旧版本号。读取已接受的旧版本时，将准确源描述与当前声明比较共同前缀。保留位置必须兼容；版本号授权这次投影，业务含义由作者保证。v1 的尾部 Link 即使在 v2 已经删除，也要在选中 State 的完整旧目录上通过校验。跨版本若遇私有槽，首片只使用同位置、同格式名的当前校验器；缺少校验器时拒绝本次加载。格式名可帮助寻找解释代码，无法证明私有字节合法。

| 审查裁决 | 理由 |
|---|---|
| 保留独立的正文语法标记、重复基数和引用目标 | 同名同版的普通 reader、标量 ID 和内嵌多个 ID 需要产生不同结果。 |
| 合并历史声明与已有 Schema 目录 | 准确 Base 已指向源描述所在的 Schema。独立表会增加第二个定位入口。 |
| 简化迁移为显式接受版本号和共同前缀 | 删除尾槽足以验证当前场景；重用同类型的位置仍需作者保证业务含义。 |
| 删除由新包重抄全部旧槽和只存哈希的候选 | 校验指纹需要另有旧描述或旧解析器才能读取健康存档。 |
| 推迟永久槽 ID、私有历史格式库及统一前置私有块 | 中间位置删除、已退役私有格式和自定义私有 Delta 各需实际消费用例。此处保留原始节点正文，方便用相同字节区分两种解释。 |

## 实验安排

复用研究提交 `0be089f6` 的文件仓与坏目录构造。在独立研究树更改 B，保留 A 的已知反例作为对照。除健康与两种坏目录外，验证同版冲突、重复槽漏边及描述复用；记录历史注册端需要写什么，检查真实 Schema 和业务对象的 Base/Delta。私有内容是独立试题，须显式说明读者在哪些情形能检查边但无法解释旧私有值。实验完成后再决定哪些格式和作者 API 值得正式接入。
