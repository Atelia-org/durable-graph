# 由发布时的 Schema 解释已退役的节点引用槽

**v2 程序只声明今天的槽并接受 v1，即可完整检查 v1 的引用，再删除退役的尾槽。** 在研究分支 `research/db105-stored-slots`，独立编译的 v1 程序写入两代 State，v2 程序读回 10 和 21、续写 34，第三个只读进程正确恢复全部三代。v2 的程序集、引用及成员声明里都没有退役的 Link 和 Padding。方案与审查合同见主线提交 `526286f1`，实验源码见 `b4d8eb9a`。主线采用独立的节点声明与登记入口，见[接入与验收](mainline.md)。

## 审查后的实验合同

采用一种新增的 Schema 描述符变体标记 B 的正文语法。复用现有 Schema 图、编号及类型表达式。业务 Base 的类型头继续指向描述符，Delta 继续使用准确前驱。每一槽按正文位置保存整数、单引用、内嵌引用序列或有界私有块的种类。前两种的一字节值可以完全相同。内嵌序列逐个检查非零 ID。对数组对象的单引用只检查一个 ID。私有块记录格式名，格式名与领域类型分别解释。描述符身份包括语法和有序槽，空槽列表也必须区分普通 Schema。

当前声明显式列出可直接升级的旧版本号。读取已接受的旧版本时，将准确源描述与当前声明比较共同前缀。保留位置必须兼容。版本号授权这次投影，业务含义由作者保证。v1 的尾部 Link 即使在 v2 已经删除，也要在选中 State 的完整旧目录上通过校验。跨版本若遇私有槽，首片只使用同位置、同格式名的当前校验器。缺少校验器时拒绝本次加载。格式名可帮助寻找解释代码，无法证明私有字节合法。

三进程实验中，下面是 v2 读者的完整节点注册。Page 的类型声明给出当前版本 2。最后的 `1` 表示作者认可 v1 到 v2 的这次投影。

```csharp
new DeclaredNode<Page>(static () => new(), [
    DeclaredMember<Page>.Int32(p => p.Value, (p, value) => p.Value = value),
], 1).Register(models);
```

| 审查裁决 | 理由 |
|---|---|
| 保留独立的正文语法标记、重复基数和引用目标 | 同名同版的普通 reader、标量 ID 和内嵌多个 ID 需要产生不同结果。 |
| 合并历史声明与已有 Schema 目录 | 准确 Base 已指向源描述所在的 Schema。独立表会增加第二个定位入口。 |
| 简化迁移为显式接受版本号和共同前缀 | 删除尾槽足以验证当前场景。重用同类型的位置仍需作者保证业务含义。 |
| 删除由新包重抄全部旧槽和只存哈希的候选 | 校验指纹需要另有旧描述或旧解析器才能读取健康存档。 |
| 推迟永久槽 ID、私有历史格式库及统一前置私有块 | 中间位置删除、已退役私有格式和自定义私有 Delta 各需实际消费用例。此处保留原始节点正文，方便用相同字节区分两种解释。 |

## 什么证据能区分两种解释

双仓实验用相同的家族名和版本号。一个 v1 作者把第二槽声明为整数，另一个声明为单个 string 引用。两个节点的原始 Base 均为 `14 03 20` 加 32 个零，Delta 均为 `00 2A 01 04`。其中 `01 04` 表示给第二槽写入字值 4。前一仓将其解为 ZigZag 整数 2，后一仓将其解为对象 ID 4。同一份 v2 注册可以读两个健康仓。整数仓一直没有对象 4，仍能交付 Value=21。从引用仓追加一个缺少对象 4 的目录，节点头和正文保持相同，此次加载在任何根、节点分配及回填前失败。

| 对照 | 实际观察 |
|---|---|
| 删除旧的单引用或内嵌序列的最后一个目标 | 分别追加缺失目标、同 ID 换成合法错型对象的目录，四种情况全部拒绝。序列前面有 null 和重复的健康目标，单引用也有独立的健康对照。 |
| Delta 以新目标替换旧目标 | 健康的新目录已经移除了被替换的旧字符串。DG 检查重放后的旧版最终状态，允许这个正常编辑。 |
| 同版 reader 改槽或改用自包含叶 | 即使正文可能读得通，完整源 Schema 与注册不符也会拒绝。反向用 B 读无槽描述的普通历史也被拒绝。 |
| 私有字节被后来的有效 Delta 覆盖 | 使用受限的同名验证器，Base 或中间 Delta 出现它拒绝的字节时均停止。换格式、删除旧私有槽或未接纳旧版本，也都在分配前拒绝。格式名相同仍依赖作者维持语义。 |

业务对象的 typed Base 继续按已有描述符 ID 路由，源 Schema 采用新目录变体（`LayoutDescriptorRecord.Kind = 6`）。每个版本的旧布局随准确 Base 的源 Schema 解析。这次选中的历史 State 的完整对象目录提供对象 ID 与实际类型。读取沿用现有全目录校验和物化顺序。该目录中的其他实际领域对象仍需要各自的绑定。

## 保存成本与复现

与 `0be089f6` 的 B 对比，在各有 8 个和 10,000 个槽位的两个工作负载中，都是同一组有三项声明的节点共享布局。首次保存节点时各多写 **116 B**。多出的 5 条 Schema 记录为 3 条槽、1 条类型表达式、1 条格式名字符串。Meta 批从 226 B 增至 301 B，Meta 目录从 154 B 增至 195 B，Meta 图封套仍为 45 B。后续改整数、改一条边都复用原 Schema 根。两种宽度三代共 18 条业务记录的原始正文、对象 ID、写入角色和 Base/Delta 选择一致。描述符编号因布局增加而改变，比较 Base 正文时已去掉类型头。万槽改一条边的 Delta 始终为 6 B。万槽中间一次保存的业务目录从 38 B 增至 42 B。目录地址编码也计入整仓增长。

在研究提交中，`experiments/RegisteredNodeProbe/StoredSlots/README.md` 给出三进程命令，`tests/DurableGraph.Persistence.Tests/RegisteredNodeEqualBytesTests.cs` 给出双仓字节与坏目录构造。目录往返和错误描述专项见同目录 `DeclaredNodeCatalogTests.cs`。局限包括同类型两个槽的业务换位、已消失私有格式的解释代码，以及多个来源版本的非前缀映射。需要这些能力的使用者可提供具体旧值与期望迁移，再扩展迁移接口。

## 万槽冷开续写的托管分配

读回的 Schema 与进程当前声明可能是两份内容相同的对象。原有 `TypeExpr.CompareTo` 对两个枚举调用 `Enum.CompareTo(object)`。当有序槽声明也要参与完整相等性比较，逐边捕获会反复支付装箱成本。用全新进程打开万槽图、改变一条边，只计随后的 `SaveGraph` 调用线程分配。两种实现分别应用相同的两行修正，按枚举的底层 `byte` 与 `int` 比较。

| 三轮保存分配中位数 | 原研究 B，由包提供历史槽 | B 从源 Schema 取槽 |
|---|---:|---:|
| 原枚举比较 | 2,419,040 B | 3,520,400 B |
| 按底层整数比较 | 239,000 B | 255,128 B |

两边都修正后，中位数相差 16,128 B，三轮中的单轮波动可达 24,624 B。两种版本、两种比较写法都写出相同的业务 Delta。研究提交 `ee2d6587` 保留这两行修正。这些采样用于说明分配来源。历史版本 Normalize 时仍会按旧行重新确认布局，此工况测量的是同版节点冷开后的保存。
