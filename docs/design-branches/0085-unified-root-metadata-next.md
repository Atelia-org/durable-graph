# DB-085：统一根的目录与轮转对照（下一片建议）

> 2026-09-30，本片已实施并通过独立验收；本建议保留原范围，实际合同、证据和下一决策转至[施工记录](0085-unified-root-metadata-experiment.md)。[固定双值实验](0085-unified-root-experiment.md)已验收，产品格式仍未选定。

## 下一片真正要回答的问题

当前单分支提交已经通过最后发布 ref 建立共同提交点。固定双值实验证明了统一根可行和有界读取，却没有证明它能减少真实 catalog/ref/locator 的独立权威，也没有消除 writer 准入或恢复全扫。

下一片聚焦：**两个分支和一次实际轮转中，能否由根选择确定的目录、各分支 head 和段视图，从而替代现有独立发布规则；省去的恢复分支是否值得新增元数据与屏障成本？** 不需要批量跨分支事务 API 来制造这个需求。

## 先收口的合同

先按需读当前 `Repository.Publish`、EventJournal 的 Create/Init/Bind、catalog checkpoint、SegmentLocator/SegmentStore 轮转和相关测试；不重读旧评审，不重复根机制辩论。

记录：**业务操作 → 受影响目录/ref/段事实 → 根固定的版本/EOF → 持久化及发布顺序 → 中断后选择与续写 → 拒绝反例 → 被替代的旧规则**。

选择一个真实操作序列作为双方共同故事，例如保留分支 A，创建或更新分支 B，并在写入过程中触发一个数据 store 从首段轮转到第二段。具体操作由源码约束决定，不要求另造批量事务。明确哪一条旧发布规则被取消或降为提示；只是给旧链末尾加总日志不算替代。

## 最小范围与防止跑偏

- 继续独立新夹具、单 writer、串行独占；优先扩展现有 UnifiedRootProbe，复用真实 RBF writer、固定 EOF、连续前缀检测和故障宿主。对接真实目录/ref/locator 语义，必要的实验适配与产品实现须明确区分，不再只把 A/B 两个数改名为分支。
- 根固定 branch name→身份、各 head，以及解析这些 head 所需的段身份/范围。旧根不能查询后来覆盖的 catalog 或最新 locator；未受影响的分支和既有地址保持。
- 先用朴素、可计量的确定版本目录作为基线，不先建设通用 CoW map、任意嵌套事务框架或通用虚拟文件系统。根定位继续有界，但不声称整个目录加载也与分支数无关。
- 一次真实数据段创建与轮转必须进入写序，不能把新段提前建好后声称已覆盖名字发布。区分内容 flush、文件名/目录持久与根屏障；本机 F1 证据和 F2 前提/图像模型分开，未实现的平台屏障不能用 no-op 冒充成功。根日志自身轮转不在本片顺带解决。
- 保留全部完整 orphan 和未发布段，拒绝未知文件或完整语义矛盾；明确重试时身份高水位、残留归属、段选择与坏尾后续写。不能默认每次失败都换新段，也不借 GC 删除难处理的事实。
- 标签、删除/归档、任意分支生命周期、Clean、快速 writer/恢复专项、平台断电交付和产品迁移均不随本片展开。若最小故事必须扩大范围，先给具体反例、可行取舍与推荐，由主线程裁决；实质目标冲突再报告用户。

## 验证、成本与停点

验证根发布前/后、回包前，候选目录和新段创建/写入/确认/选择各关键窗口；覆盖恢复再次中止、重试、正常续写和独立进程冷开。保留旧根视图、完整前缀/hash/地址；完整坏根或所选依赖坏不能回退，I/O、取消、预算失败不能通过。真实 kill、注入和模型分别报告；优先新增风险窗口，不机械重跑所有旧矩阵。

计量完整提交、成功追加字节、元数据写放大、flush、Open+首次读取、恢复总量与残留文件数量。除历史/失败残留轴，还改变无关分支数量，识别 O(分支数) 的全目录复制/加载成本。请求/返回、预取、耗时、线程分配与未计量的元数据 I/O 分开；不把进程冷开当作 OS cache 冷。

按相同业务语义列出两条路线的操作与失败状态。能共用夹具和责任时才给数值对照；若候选尚未承担真实 DG 图/Schema 的责任，明确差额，不算产品性能倍率。是否更简单须同时看减少的发布/恢复规则和新增的目录、身份、残留处理责任，不能只数代码行或成功用例。

**停点是路线裁决证据**：推荐继续统一根、保留原路线，或指出还缺哪一个决定性证据；不自动转入产品格式重构。若证据支持继续，应给下一次具体交付，而非预先铺开长期分片清单。
