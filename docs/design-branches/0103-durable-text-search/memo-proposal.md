# DB-103 · DurableText 搜索：memo 的下游使用提案

> 下游原始提案，保留当时的候选签名、使用场景和缓存设想。现行设计从[一期设计](README.md)进入。

memo 希望对手中的一份 `DurableText` 直接查找字面文本，或用同一个 .NET `Regex` 扫过多份正文，取得命中位置并按需停止。文本如何分片、何时拼成连续内存、临时缓冲区何时归还，都可以由 DurableGraph 决定。本页是 2026-11-19 的下游提案，供比较 API 和实现时使用；文中的新签名尚待选定。

## 调用场景

一个角色可能有约 1000 篇条目，每篇正文约 4000 字。这是估算的实验负载。比如角色刚把“钥匙在北门仓库”改成“钥匙在南门仓库”，同一回合就应当能找到新地点，无需先保存。回溯到旧世界以后，搜索该角色的旧正文仍应找到北门。

由 memo 选择当前世界、角色、条目和字段。`FullText`、`Summary`、`Gist` 分别搜索，命中后 memo 附上条目 ID、字段和上下文片段。DG 处理一次调用所给的一份逻辑文本。正文作为普通领域对象常驻，或由 memo 从 `GraphRef` 按需打开，都可以使用同一接口。

## 期望的 API 形状

```csharp
// DurableText 的候选公共成员
public TResult VisitSpan<TResult>(Func<ReadOnlySpan<char>, TResult> visitor);
```

每次调用固定进入时的文本版本，同步调用 visitor 一次，输入是整篇逻辑正文的连续 UTF-16 单元。空正文也调用一次。把 visitor 的返回值直接交还调用者；若它抛异常，释放本次调用临时占用的资源并传播异常。这里的访问单位是**整篇正文**。搜索方式、何时停止枚举、是否提取命中文字都由调用者决定。需要跨次调用持有同一文本版本时，可比较在 `TextSnapshot` 上提供相同入口。

```csharp
// regex 由 memo 构造；绑定到它的委托只在条目循环外创建一次。
Func<ReadOnlySpan<char>, bool> contains = regex.IsMatch;
foreach (var entry in entries) {
    if (entry.FullText.VisitSpan(contains)) { hits.Add(entry.Id); }
}
```

需要位置时，visitor 可在内部遍历 `regex.EnumerateMatches(span)`，取够结果就停止，返回独立的 UTF-16 下标、长度或结果列表。字面搜索可以沿用快照上已有的流式 Ordinal，也可以在 visitor 里使用 span 的标准比较函数。一次 visitor 内可对同一版同时查找、截取片段，只有需要带走的文字才复制。

**可选便利接口。** 若调用点经常需要 `foreach (var hit in text.Matches(regex))`，可以单独比较这种形状。若返回已收集的范围集合，调用简单，一次取全；若返回惰性序列，应明确序列固定哪一版正文、由谁持有底层存储、提前结束时如何释放。如果直接返回 .NET 的 `MatchCollection`，还要考虑它对输入字符串的持有。memo 可以直接用 `VisitSpan` 达成首个用例。

## 生命周期与可观察行为

| 场景 | memo 期望观察到的结果 |
|---|---|
| 跨片与定位 | 对“去仓库”插入“北门”，一次 visitor 看到“去北门仓库”；Ordinal 搜“北门仓库”得到起点 1。换用含补充平面字符的前缀，偏移仍可原样用于同版的 `CopyTo`。 |
| 回调内枚举正则 | 以同一 `Regex` 匹配整篇字符串作对照。覆盖跨片、跨行、无匹配及零长度命中。例如在“北北”上用 `(?=北)` 得到 `(0,0)`、`(1,0)`，visitor 也可在第一项直接返回。 |
| 同线程编辑与重入 | 外层收到“甲甲”，回调中把编辑器改成“乙”并再次调用 `VisitSpan`。内层看到“乙”；内层结束后，外层 span 仍读作“甲甲”。两次调用各自在返回或抛异常时结束其借用。 |
| 结果寿命 | 公开签名保留普通的 `TResult` 泛型约束。在安全 C# 中，返回值可为布尔值、范围或自有字符串；编译器拒绝将输入 span 或引用它的 `Regex.ValueMatchEnumerator` 作为 `TResult` 带出。 |

最小验收是在由编辑产生的多片正文上，用同一委托搜出跨片命中，并在嵌套编辑案例中读回正确的内外两版。签名另用 .NET 10 临时程序作了编译对照：循环外绑定的 `regex.IsMatch`、返回首个匹配位置的委托均可用；尝试返回 span 或正则枚举器，均报 CS9244。这项检查只验证调用形状。

## 供 DurableGraph 比较的成本

单片正文（包括底层字符串的一个切片）可直接提供 span。多片正文必须为这次连续访问准备完整的连续表示；可比较每次租用临时缓冲、内部保留缓冲并按需刷新、按不可变版本缓存字符串。借用在 visitor 返回前一直有效。若内层查询遇到已经变化的正文，外层正在使用的数组既不能覆写，也不能提前归还。选择租用策略时，成功、异常和嵌套三条路径都要满足同一合同。调用名表明访问有明确作用域，文档还应写清首次或编辑后访问可能复制整篇、需要 O(n) 时间和空间。

在 1000 篇 × 平均 4000 字的估算负载下，可比较首次全库扫描、对未变文本重复查询、仅编辑一篇后再扫。分别记录完整查询耗时、分配量和查询后保留的内存，注明单片和多片比例。委托与正则在循环外建立，才容易区分文本准备与调用方构造查询的开销。

### 候选：一个可复用数组，按调用借还

在编辑器现有的串行使用约定下，`VisitSpan` 可在内部借用连续文本，调用 visitor，并在 `finally` 中归还**本次取得的借用**。借用记录给出有效范围及归还方式。区分两个问题：数组里的文字是否仍对应本次目标版本，以及数组此刻能否覆写。前者可由缓存的 `ContentToken` 与进入调用时的 view 的 token 比较得到，后者取决于活跃借用。现有编辑会生成新内容标识，保存时单纯重绑或压平可以保留标识。缓存刷新成功后才登记新标识。

一种较小的候选实现给每个实际需要展开的编辑器留一个自有 `char[]`，记录版本、有效长度和这个数组的借用数。空文本及单片直接访问。多片命中相同版本时增加借用数，即使重入也可以共享。版本已变且借用数为零时，先使旧缓存标识失效，再按需扩容并填充；只向 visitor 提供正文长度。版本已变但数组仍有人读时，本次嵌套调用从池租一块独占的临时数组并复制。主数组的归还只减借用数；临时数组在本次调用结束时归池，准备阶段失败也须归还。临时结果无需提升为主缓存，代价是稍后访问新版可能再复制一次。只编辑而未嵌套访问时，旧借用保持稳定，下一次访问可以原地刷新。

这样常见路径只维护一个缓存槽，长寿命编辑器释放时自有数组交给 GC。若主数组也打算从池长期租用，应一并比较它的归还时机、过大容量的滞留和实际分配收益。可用三条轨迹对照不可变字符串方案：同版本重复读取、每次编辑后查询、嵌套编辑后内层抛错仍能继续读外层旧版。
