# DB-085：统一根首个机制实验

> 2026-09-30，已完成并通过 Astra high 独立只读验收；本片停点无阻塞。依据[统一根对照](0085-unified-root-comparison.md)及本轮用户授权；只在新建独立夹具运行，不迁移产品格式。主线程维护合同，Sol xhigh 实施，最终 Astra high 独立只读验收。

## 问题与停点

两个追加文件同时变化时，一个固定形状的系统根能否成为唯一业务发布判据，使未发布的完整数据留盘但不可见，并在真实中止、恢复再次中止后安全续写？
成功标准是旧/新完整 pair 的可观察选择、完整事实及地址保持、拒绝反例、全过程成本；不是只演示一次成功提交，也不据此宣称 DG 多分支、tag、轮转已简化。

## 共同合同（实施前）

| 根字段/子视图 | 覆盖的事实与依赖 | 持久化顺序 | 发布权限 | 重开选择 | 拒绝反例 |
|---|---|---|---|---|---|
| 根格式、物理槽身份、两个子视图 | 固定 `a.rbf`、`b.rbf` 的确定身份、head ticket 和含 Fence 的可见 EOF；格式只属于实验 | 初始化已建立文件及名字；交易不新建/替换文件 | 仅根决定 pair；子文件尾部不独立成为业务 head | 固定根物理长度，按 EOF 格点定位末完整根；不扫描历史寻找“好根” | 未知格式、完整坏根、所选依赖坏 CRC/语义、越界、缺文件均拒绝 |
| 子视图 head/EOF | 当前值与身份；读取只接纳所选版本，物理 orphan 不自动成为 head | 两文件追加后各自 durable flush，才允许开始根追加 | 子层只产出候选地址 | 旧根继续选择旧 ticket/EOF，不查询可变 locator/catalog | 新数据存在不能改变旧根；EOF 外合法帧不能被旧视图读穿 |
| 根的完整记录 | 下层屏障完成的因果见证，不是根本身 flush 已完成的证明 | 根 append → 根 durable flush → 回包 | 完整未回包根也不能按调用者未知而删除 | 完整根选新 pair；支持短根尾只能选择其直接前驱，不循环回退 | 完整根坏、已选依赖坏、I/O/取消/预算耗尽不能回退 |
| 续写物理前沿 | 所有完整记录含 orphan 保留；身份以文件和完整记录位置确定 | 同锁下重新检测/资格 → 关闭候选 → 复核 → 必要截断/flush → 全新打开和依赖确认 → 根确认 | 只有显式离线恢复可改短尾；普通读不修复 | 重试从盘重推；不使用上次报告作动作计划 | 多短尾、Trailer 1–11B 未决、完整矛盾、检查未完成不得执行 |

正常读取的有界根定位依赖本实验固定槽格式和受控 writer；不能将随机 CRC 成功推广为任意 RBF 物理成员证明。实际改尾必须复用连续前缀检测，完整记录的固定形状/依赖检查也必须完成。正常只读成本与离线恢复成本分别计量。

完整 orphan 保留，不复用其地址，不重新采用它们构造业务视图；后续新增记录可以越过完整 orphan 继续追加。短尾无已交付完整记录身份，处理它不等于重用完整事实。若固定尺寸不适用于 DG 的 Schema/RefId，另需身份分配协议，不能从本片推导已解决。

初始化名字持久属于前置条件；Windows 上的进程 kill 不能证明目录项抗断电。本片通过 F2 模型分别展示名字丢失、屏障失效、旧范围损坏和未确认根被后继依赖的风险。真实 kill、可重复故障注入、模型图像各自标明。

## 验证与计量计划

- 真实 Append 部分写、依赖屏障前后、根完成/屏障/回包前中止；恢复截断前后、未完成屏障、重新确认与交付前再次中止；重试、正常续写、独立进程冷开。
- 完整坏根/坏依赖/语义矛盾拒绝且不改盘；锁竞争、I/O、取消、预算失败不冒充一致；旧视图与 orphan 隔离；全部已存在完整前缀的内容和地址保持。
- 分别改变历史和完整未发布残留数量。计量完整提交/屏障、Open、首次读取及合计；恢复另计检测、资格、动作/确认及总计。计量范围必须覆盖直接读和 RBF 读取，不重复合计嵌套 scope。
- 请求/实际返回字节、读取次数、预取、耗时、线程分配单列；OS cache 未控制，分配不是峰值内存，返回字节不是设备 I/O。预算范围据实现明确。
- 现产品 S0 是多格式/所有完整事实依赖检查，两个固定值实验责任较小。可列协议步骤与相同机制的成本，不能直接用二者耗时比宣称 DG 加速；不能用少检查换来比较优势。

产物与结果在本记录补充；公开 Open/writer/Audit/rescue 保持，未冻结通用 API，不自动进入全面重构。

## 实验实现与证据边界

实现位于 [UnifiedRootProbe](../../experiments/UnifiedRootProbe/README.md)。不依赖 DG 的业务模型，也不把根叠加在现有 ref 发布链后；这是替换发布判据的隔离机制见证，尚未把 DG 的真实目录纳入根。

- `a.rbf` / `b.rbf` 的首帧各存随机文件身份，随后每条值帧物理占 60B。根帧物理占 108B，含 generation、两组文件身份/ticket/可见 EOF；固定序号槽可直接定位，不引入持久索引。ticket 不含最后 4B Fence。
- 正常 `Open` 只读取一个根槽，第一次 `Read` 校验两份所选子记录和身份/边界。短根尾另做有界的现存字段和新一代依赖核对；不是遇错搜索旧根。Recovery 才从 Header 开始取得全部连续物理成员证据。
- 本片每次 `Commit` 是一次全新 writer 准入：全量资格检查、A/B/root 旧范围确认，然后追加 A/B、分别确认、追加并确认 root。即每次正常 Commit 包含六次 durable flush；不能把仅三次发布屏障称作完整成本，也尚未取得快速 writer 证据。
- 恢复重试重新检测三个文件，保留全部完整帧；候选关闭后才在同一个独占锁内复核并处理一个合格短尾，随后全新严格资格检查并按 A/B/root 确认。无动作恢复也包含三次确认；有动作另有一次截断屏障。
- `readBudget` 覆盖第一轮资格中的物理扫描、候选/语义 RBF 读取和固定尾部直读。动作前复检与最终严格资格不受此预算限制；目录/长度查询、CPU/内存也不受此预算限制。预算耗尽不是通过。计量则覆盖完整入口的实际读调用。
- 真实中止通过 RBF 实际写钩子和宿主外部 Kill；确定性 throw、字节损坏/持久图像模型分开。模拟一个成功 flush 后仍丢依赖会拒绝，不能把这类超出存储保证的故障降级成恢复旧根。完整已确认后缀若被外部整齐删除，单靠这个根日志也没有独立防删除证据。

最后验收只回答固定双值机制的问题；真实 Schema ID/RefId 分配、历史读取闭包、多分支/tag 的目录更新成本、轮转和文件名持久性仍没有从本片取得证据。

## 实测结果（2026-09-30）

### 正确性与验证

全 Release、显式源码联调，专用 C: TEMP/TMP，所有 .NET 串行，保留 `ShouldUnsetParentConfigurationAndPlatform=false`。

- 根 solution 构建通过，24 个既有上游 XML 注释警告；Persistence 1,152/1,152 回归通过。最终实验构建 0 警告、0 错误。
- 最终 15 组可执行自测通过，组内另含多种损坏/尾长/故障变体：合法缺 Fence 可恢复；CRC 正确但 refs/descriptor 矛盾拒绝；Trailer 1–11B 未决拒绝；完整根/依赖/orphan 损坏拒绝；取消、预算、锁与 I/O 不授予动作资格。错误断言明确接纳 InvalidDataException，不用任意异常冒充正确拒绝。
- 主矩阵 53 个案例全部通过：16 个提交窗口、三种短尾各 10 个恢复再中断窗口、完整根未回包后 7 个无动作恢复窗口；共 90 次真正外部 Kill。每例恢复成功后立即独立 inspect，再正常提交与独立进程冷读，不用第二次恢复掩盖首次交付结果。
- 最终 DLL 再抽查 root 短写 → 恢复截断后屏障前 Kill → 重试 → 正常续写 → 独立冷读，通过（另 2 次 Kill）。独立审阅者重算两批各阶段完整前缀，762 项 SHA-256/固定 offset 检查全通过。
- F2 仅是明确的字节图像模型与真实写序/屏障 hook：名字丢失、根在但依赖丢失、旧范围破坏均拒绝；可读未 flush 的完整根在模型中可消失；后继同根文件提交先确认前继。它们不构成 Windows/硬件断电保证。

首轮静态/运行检查修正了资源二次打开、0B 字段前缀、短根完整矛盾检查、合法缺 Fence 被过度拒绝、动作复检取消误分类，以及宿主将计时字段误作文件变化的判断。首次编译和失败日志均保留。最终普通 Open/writer/Audit/rescue 产品代码未改；上游仅新增实验程序集的 internal 访问声明。

## 结论与下一交付

**固定双值场景的统一根机制成立；尚不能证明整体 DG 比原路线更简单。** 根可以在不删除完整 orphan 的前提下选择一致版本，有界读取也没有转移成首次全扫。物理修尾、重新确认和写入准入仍有全历史成本，本片没有快速 writer 或快恢复结论。

当前 DG 单分支提交本身已以 ref 最后发布；这个小实验没有发现原路线在同等单分支责任下缺少一致性。新路线潜在收益在于让 catalog/ref 集合与 locator 也服从同一版本，而不是单纯多放一个根记录。应继续小范围检验两个分支和一次轮转是否能真正替代这些独立权威，并计量目录更新和残留成本；在取得该证据前，不切换产品格式或公开路径，也不自动启动全面重构。
