# DB-102 五项主线改进验收

产品起点为 `7f9121fa`；实施前的计划提交 `27b887ef` 与其产品及测试源码一致。各对照臂依次加入一个产品改动，均以固定 Storage 源码 `3f780ad9` 做 Release 解决方案构建。普通 05-care 宿主取自应用 `b918d5a1`，每个消费方目录固化 19 个 DLL 的 SHA-256。四个 DurableGraph 产品 DLL 从对应干净提交构建，其他 15 个 DLL 与原普通宿主逐文件一致。性能比较保留每臂的产品提交、二进制指纹、入口、输入、次序和分组。

以下耗时均为本机墙钟，MB 使用十进制的调用线程托管分配。首次进程执行含操作触发的 JIT，OS 文件页可热；预热进程内重开 Repository 和同一 Store 再读分别列示。诊断计数来自计时外的运行。

## 最终产品与起点

05-care 续写至第 231 步，同一关闭存档，四个版本调换顺序做四组，共 64 个独立进程、256 次恢复。每次核对业务根及序号，应用核对 58 个操作 ID；每进程退出后逐一检查原存档 10 个文件的 SHA。六个累计版本另各自从原始 230 个 Event 重放、续写第 231 步并重开，逐步业务与物理见证一致，续写仓均为 2,942,640 B。

## 产品行为与验证

1. **Event 环境，`a13d5771`。** 单独恢复 Event 时仍验证业务快照、取得独立的可变根，成功物化后才替换 Repository 的单槽。双图 `ReadCheckpoint` 继续分别验证和读取两张图。在第 231 步存档逐条读完所有 Event 时，普通产品槽在第 1、2、3、36 次读取后更换。调用计数副本独立核对建环境 231 → 4；普通程序集核对了 231 次准确图校验、应用的 58 个操作 ID 及终态。以 4 个和 8 个独立活仓测量，清槽后各释放约 30,296 B/仓，弱引用回收；该数取决于实际 Schema 与已建立的绑定。[资格与失败回归](../../../tests/DurableGraph.Persistence.Tests/RepositoryModelEnvironmentTests.cs)
2. **目录后缀回放，`aa21c929`。** 仅在还有 Delta 时复制一次已验证的 heads，在私有映射上逐层校验，完整后缀成功后冻结一次。真实仓全部 469 个目录、235 个物理 Delta、49,154 项有序 ID/head 及每个版本的累计有效载荷 H 与通用解码器一致。按物理顺序读取全部地址，禁用缓存时两臂均解码 Base 469 次、应用 Delta 26,806 次，后缀内新生成完整目录的次数从 26,806 降到 235。8 MiB 预算下前驱驻留，多数读取已很便宜，两臂各应用 235 层、生成 235 次完整后缀结果。机制诊断与来源指纹可由 `git show 2b7453e2:experiments/DirectoryDictionaryMechanismProbe/land-census/README.md` 复核。[畸形输入及跨层差分](../../../tests/DurableGraph.Persistence.Tests/DirectoryBulkReplayTests.cs)
3. **业务字典，`2f5d4b5e`。** 临时编码缓冲由一次非空索引扫描独占。每个键仍有自己的准确持久字节并接受原有校验。覆盖大键后紧跟小键、空表、重复键与合成应用单点编辑。[编码差分回归](../../../tests/DurableGraph.Tests/DictionaryIndexScratchTests.cs)
4. **State 保存准备，`e4b1c1d9`。** 同一次业务 State 保存采用固定 catalog，按完整布局共享头。规划沿用各类型的计量方式，包括 DurableText 的分段估算。选中 Base 后按实长拼接，安装 H 按实际记录计量。实际 230 步共有 47,800 个候选，头编码降至 2,026 次。逐步比对共 108 个移除 ID、1,102 条实写记录（775 个 Base）、来源地址、长度、完整正文、全体安装成员 head/H 与文件增长。4,096 叶图的头编码从 12,293 降到 6；无改写零条，单叶更新写一个 Delta，强制重写选中一个 Base。[规划边界回归](../../../tests/DurableGraph.Persistence.Tests/ObjectRevisionPlannerTests.cs)
5. **标签解析，`0f5bf47a`。** 保留 `ResolveStoredTag` 的完整描述校验。对 16/64/128 个既有名称各命中一次，父版本共读描述 32/128/256 次，产品版为 16/64/128 次，找不到名称均为零次。故障、损坏目标、排序、关闭与只读重开由现有测试及普通消费方验证。[内部校验](../../../src/DurableGraph.Persistence/RepositoryResources.Bookmarks.cs)

## 两处异常及裁决

- **历史签出后的首次热 LoadState。** 父子工作副本都还活着，第 115 步子签出后再次读同一 State，两臂均零重放。首轮两对由 4.66 / 2.73 ms 升到 17.11 / 20.28 ms。保留相同前置操作，以四个独立进程再测，首次读为 3.50 / 4.38 → 4.48 / 4.51 ms。签出后连续 16 次读的组内中位为 3.85 / 3.65 → 4.02 / 3.72 ms；另一组新仓预热后为 4.02 / 3.99 → 4.16 / 3.82 ms。128 次重复读均无目录重放，两臂中位分配相同。原两次慢值保留，未能确定成因；复测未复现持续十余毫秒的退化。采用批量回放，其收益集中在确有后缀可回放的入口。
- **大图单叶更新。** 4,096 叶合成图的总保存时间，原两对变化为 +4.45% / −16.06%，新增两对为 +7.39% / −5.43%；四对分配均减少约 18.06%。无改情形补测的两对总耗时下降 12.82% / 21.05%。采用 typed Base 准备改动，依据是减少重复头编码、230 次真实保存收益及逐步写入一致性。该合成单叶更新的端到端延迟仍无稳定改善。
