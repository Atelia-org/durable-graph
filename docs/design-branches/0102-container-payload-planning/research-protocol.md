# DB-102 开题报告：容器准备与对象重整怎么选

2026-11-18 · 开题时冻结的测量协议，研究结果与主线采纳状态见本目录入口。研究对象是业务 State 保存中 List 的 payload 准备，以及业务对象之间的可选 Base 重整。起始 DurableGraph 为 `b9eef489275415bdcc0f743c6d86702d52b4138f`，Storage 为 `3f780ad95239d7556f917e1adca6839cda144c92`。产品行为、术语和已有候选见 [DB-102 入口](README.md)。

## 1. 要作出的决定

1. 哪些 List 值得延迟生成完整 Base？在**相同落盘结果**下，少编码、少分配能给一次真实 State 保存带来多少收益？选中 Base、列表很小和变长计量较贵时又付出多少？
2. 各对象自行决定重整能否取代图级预算？跨对象协调能削平多大的写入尖峰，能否把冷开延迟或累计写入降到值得保留协调逻辑的程度？
3. 链上实际字节数 `H` 是否足以预测这批负载的恢复成本？List reader 每应用一层结果非空的 Delta 都会创建一个结果全长的数组。少量 patch 字节可能对应大量元素复制。需要在**相同逻辑内容、不同链深**下观察它是否影响整图冷开。[恢复循环与 ApplyDelta](../../../src/DurableGraph/Runtime/Containers/ListStateReader.cs)

结题可以选择现状、局部改进或组合方案。可修改 API、格式及上游来做有判别力的实验，无旧数据兼容约束。实验分支可直接重建仓库。第一场保持相同格式和选择结果，是为了归因；改变格式的后续方案单独与优胜者比较。本课题交付可运行原型、证据和产品建议，合入产品由后续决定。

## 2. 候选组合与出场顺序

下表中的“基线”固定 List 的 Adaptive Delta，以及 DurableText 等其他对象在起始版本的产品行为。现行策略使用阈值 5、预算 5%。新增、强制重写或更新时 `B ≤ D` 等必写 Base 规则在各策略间共用。`B` 含类型头及对象版本封套，`D` 还含准确前驱地址。

| 组合 | Base 准备 × 可选重整 | 必须取得的数据或出场条件 |
|---|---|---|
| 基线（必测） | List 立即编码 × 现行图级预算 | 跑全组负载，留下未优化的端到端数据、逐步实际记录及编码计数。另以同一程序重复跑基线，估计环境波动。 |
| 精确延迟（必测） | 固定宽度从 Count 精确计长；Int32、引用 ObjectId 扫冻结元素精确计长；其他类型沿用现行准备 × 现行预算 | 与基线共用编码器和 Delta 字节。分别报告固定宽度、变长整数、变长引用的净收益和回退工况。精确计量通过后，按类型选择进入策略实验的准备方式。 |
| 对象本地（必测） | 与图级对照完全相同的准备 × 有更新的对象在 `H+D > 5B` 时立即重整 | 与上一步选定的图级对照逐轨迹成对运行。从第一步提交起独立形成历史。单列仅换选择函数的成本，以及落实本地决策后实际删去的汇总、计量或分配。 |
| 每次一项（条件） | 相同准备 × 每次至多选一个可选 Base | 本地方案出现同次多项重整造成的尖峰时进入。对全体越线对象单遍取最高放大率，平局按 ObjectId；包括未改的积欠对象。与前两种策略比较尖峰和积欠消化速度。 |
| 按额外字节审批（条件） | 相同准备 × 保留原排序和预算来源，更新只收 `B−D`，未改收 `B` | 在同一批候选中观察到按完整 B 收费会推迟可容纳的更新时进入。先只换收费口径，保留首项超支与前缀停止规则；比较新增获批项、额外写入、后续冷开和积欠。 |

其他路线按瓶颈进入。变长扫描占明显成本时，比较扫描与在必经捕获循环中顺便计长；只在“已证明未改”的列表上评估沿用前版精确 **Base** 长度，冷开缺少该事实时回退。`H` 不能充当这个长度。Base 编码消除后，若 Delta 匹配或选中 Base 的中间复制占主导，再试复用 Delta 计划或单 writer。若大表长链先拖慢冷开，再比较链深触发与改善恢复侧的方案。全面两阶段、并行编码、先编码再回退等储备路线，须指出它要改善的实测瓶颈、最便宜的对照和新增所有权成本，才加入矩阵。新增组合写下触发样本与预测，再跑正式对照。

## 3. 必测负载及有效性见证

以下规模是起跑值。先用 pilot 确定耗时和是否触发预期机制，再冻结正式脚本、输入、采样点与哈希。机制工况允许压缩；业务原始轨迹保留原尺度。每条都要有一次真实提交和从已发布版本恢复的见证。

| 负载 | 输入、编辑与比较组合 | 能作判断的条件 |
|---|---|---|
| 小表与大表、稀疏与密集 | 基线与精确延迟。固定宽度选 byte、double，变长选 int、引用。用 16、4,096、65,536 项覆盖小中大；各族取小、大两个端点，中档用于定位转折。测未改、单项替换、尾追加、密集替换，另列首写和新增对象。 | 命中“不写对象记录”“选 Delta”“选 Base”。整数和值宽度变化、ObjectId 跨 127/128、Count 或 typed body 长度跨 varint 边界均有见证。引用分别用重复引用和不同子对象，保留一次只改子对象的检查。 |
| 同步越线与转冷 | 当前图级与本地必测，满足条件时加挑战者。起跑用 32 个同尺寸中等 List，让每步 Delta 小于 Base，调整编辑比例直到默认阈值下多项同期越线。随后冻结其中大多数，只更新少数热点。 | 同次出现至少两个可选请求，现行预算实际推迟其中一项。记录越线前、尖峰当次、冷却末的真实历史与冷开。积欠从实际延期形成，追踪每个延期对象何时清理；停止变化的对象自身不会继续增加 H。 |
| 大表微改、链深与恢复 | 图级与本地必测。对大表反复替换一个元素，在 1、8、32、128 个 Delta 附近选取实际链深。各取样点另建相同逻辑内容的单 Base 对照。 | 同时获得链项数、H、结果数组分配与冷开耗时；分离内存中 codec 的重放和整仓重开。明确记录各路是否曾越线。若策略已选 Base，按实际链深报告，无越线本身也是观测。 |
| 消费方原尺度 | 基线、精确延迟、对象本地三路均测。使用 one-turn-trpg 的 05-care 真实试玩事件，走当前应用的业务变更和 State 保存入口。终态另取全关重开与续写见证。 | 活跃 History 追加与归档回合并存。给出每步实有 List 数、长度、变更数，报告 State 保存占整步的比例。压力放大后的样本独立列为合成负载。 |

**业务输入。** 05-care 在兄弟仓的 `experiments/seed-generation/random-worlds/playtests/05-care/private/debug.json`，3,768,129 字节，SHA-256 为 `64A81538A630CA1FE40B30F5C7624A9184B2333BE6C3990DFA5CACB25F4C1FF9`。开题只核查了结构与代码。序号 1–230 连续，终态 7 个归档回合的 History 各有 22–24 项。执行时从相同初始 GameId、初始 State 按顺序离线回放，比较每步逻辑指纹、最终视图及归档历史。实际 Dispatch 每步提交 Event 再提交 State，分别计时，端到端统计同时保留整步。私有正文留在原仓；提交复现命令、摘要、输入指纹及所需版本。若当前应用转移器无法重放，定位第一处差异并修复适配或补齐准确来源；形状模拟另列，真实轨迹仍记待测。

消费方定位从 one-turn-trpg 的 `src/OneTurnTrpg/Persistence/GameSession.cs` 和 `StoredModels.cs` 开始。原试玩来源为 `fbdb559`，输入的 Git blob 为 `acfe5f66edd8ebbc93a9151ec7c4429de734d15f`。工作树与 Git 的行尾配置可能影响文件 SHA，执行清单同时记录 blob 与实际读取文件的 SHA。逐步逻辑核验在计时外、独立诊断轮进行；保留一份从原导出得到的预期终态，对照各臂，避免几个实现共享同一回放错误。

**语义边界。** 同策略精确准备逐保存核验对象记录种类、实际 payload 长度与 body 哈希、准确前驱、发布后的 head/H；相同物理布局时逐字节比对。不同策略容许不同历史，每路均要核对自身实际链、成员、引用身份、业务内容及冷开后再保存。覆盖强制重写、准备后放弃、失败不推进基线、未改对象可被选中重整。现有 [计量与续写测试](../../../tests/DurableGraph.Persistence.Tests/BusinessPlanningAccountingTests.cs) 和 [List 图回归](../../../tests/DurableGraph.Tests/ListGraphTests.cs) 可作断言来源。旧 [List 回放器](../../../experiments/ListDeltaReplayProbe/PROJECT-STATE.md) 仅借编辑脚本；合成轨迹可借[本次基线的 SaveGraph 探针](../0104-text-editor/README.md#native-text-sources "Git 06c57dd4:tests/DurableGraph.Persistence.Tests/DurableTextProductProbeTests.cs")搭建。

## 4. 逐步保留什么数据

| 观测单位 | 字段与口径 |
|---|---|
| 一次保存 | run、策略、负载、step、编辑、对象数；总墙钟时间、分配字节；分列捕获、Base 计量/准备、Delta 准备、选择、选中后编码、追加/安装/发布。标注计时嵌套与未单列开销；线程分配标明线程范围。每阶段注明单位。 |
| 一个候选与一次写入 | 目标对象的 Count、变更分类、B/D/H、链深、Base 编码次数/字节、Delta 候选字节、可选请求/获批/延期原因；实写种类、body 哈希、payload 字节、前驱及安装后的 H。用独立诊断轮补测未编码候选的准确 B，避免为了观测而在计时路径强制编码。 |
| 一条保存轨迹 | 逐步对象 payload、可选重整额外字节、累计追加、数据/控制文件增长；按运行分别给出中位、P95、最大及触发步骤，首写单列。区分对象记录、共享批次和整库文件，文件增长不等同设备实际写入量。 |
| 一次恢复 | 明确目标提交和链深；新进程/新 Repository 的打开、整图物化、恢复后续写计时与分配。记对象链项数与 H、实际批次解码、目录重放和缓存命中。记录 OS 页缓存条件；codec 内存重放另表。[分组读链及物理计数器](../../../src/DurableGraph.Persistence/GraphRecordStore.cs) |
| 一个可交付实现 | 相对基线新增/删除的跨层接口、每对象常驻状态、临时分配、遍历/排序次数、必须维护的所有权与失败路径；区分探针接线和产品必需代码。用这些具体差异解释复杂性取舍。 |

## 5. 测量、异常复查与结题

1. **先校准再计时。** 主线程固定工作树与依赖 revision、Release 构建、SDK/runtime、机器和数据盘、GC/JIT 设置、脚本/种子、程序及程序集哈希。预热两路。先跑正确性和机制计数，再在独立运行中测端到端；详细 tracing、哈希、读回、报告写盘置于计时之外。先作同版 A/A，依据重复差异定下本轮可分辨的量级，写入运行清单。
2. **成对独立运行。** 每臂每次使用新进程和新仓库，同一机器串行跑性能轮。两臂起跑取四对、AB/BA 各半，多臂轮换顺序。每个重复内按相同编辑序列提交；保留每步原值，报告独立运行间的配对差和范围。短序列 P95 附样本数及最大值。若差异与基线波动相当且会改变裁决，补一批同规模成对重复，仍分不开就报告当前分辨率。
3. **保留异常并追因。** 先定位版本、run、具体提交和对象，检查输入及落盘账目，再拆看计数、JIT/GC、flush、批次共享与计时代码。真实慢样本进入尾部统计。轨迹没有越线时保留原结果，另建能越线的 fixture 重测。遇到指纹错误、观测缺失或计时器干扰，在清单标记失效原因；正确性失败归在该实现版本。修复后记录新源码/构建身份，在相同条件重跑受影响的完整配对组，建立修复前后索引。
4. **逐项裁决。** 先过正确性，再看同一机制的计数和端到端成本能否相互解释。编码候选按类型分别晋级；只改善合成大表时限定其适用范围。策略同时列出同步写入最大值/P95、累计写入、积欠持续时间、冷开分配/延迟和能删去的复杂性。若一项明显占优且其他关键指标未见可分辨的恶化，推荐较优者；差异落在波动内优先简单者。若互有胜负，以实测交换量给出默认建议、受损工况与改选条件。无业务延迟目标时不虚设综合分数。
5. **完成清单。** 在本目录留一张对照表，每行为“组合 × 适用负载”，附源码和独立复现命令、原始样本位置/哈希、正确性见证、异常处理、裁决。必测行都有有效数据；条件行要么已测，要么链接实测触发指标并说明为何不进入。主线程复核关键源码、抽核原始逐步记录，独立重跑基线与推荐组合的关键反例。代码改动按仓库约定完成根构建及相关测试。候选若只完成局部实验，应标明尚缺的端到端证据。

执行中可并行委派探针/编码、策略、消费方回放和独立复核，写入范围用独立 worktree 隔开。主线程统一输入和指标口径，串行调度正式跑分；按首轮数据淘汰、补测或修正。收口时报告保留、淘汰、条件适用和未能验证的项，并给出研究结论与产品合入建议。
