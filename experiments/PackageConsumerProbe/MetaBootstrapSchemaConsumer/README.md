# Internal meta Schema package consumer

This DB-087 P1b witness consumes freshly packed Runtime and Persistence packages. An isolated console uses the existing `Atelia.DurableGraph.Persistence.Tests` friend name to access the internal experiment; it grants no public API or migration qualification.

The packaged generator builds the host's Base/Point/Key/Root model. Packaged employee DTOs/bodies persist and recover its full base, inline and Nullable Schema closure, with a `List<Point?>`. The host also contains `List<long?>` and `List<List<int>>`; every outer position shares one inner `List<int>`. Arrays add a 128-element `int?[]` and a 16×8 `Point?[,]`. Two Dictionaries contain 128 entries each: `Dictionary<int,long?>` and `Dictionary<Key,Point?>`, with a complete inline Key of `int` and `int?` fields.

Four separate processes seed, read meta before registering business models, continue with nine real Delta records, and verify old/new State content. The builtin-only List, Array and Dictionary headers, including their actual Base/Delta bodies, are decoded with an empty model registry and no catalog. Complete business graph reading still uses its exact Schema root. Wide Int64 values, Nullable changes, the outer resize, every element and shared inner identity are checked. Both arrays retain their zero-based dimensions. Dictionary changes remove, add and patch values, then reverse enumeration within the same live instances; all complete keys, values and recorded comparison policies are checked after cold restoration. The builtin map retains ScalarDefault and the inline-key map retains CurrentDefault; the latter's comparer must distinguish keys with the same `int` and different `int?`. Every sparse change preserves its ID and exact prior. User containers use the dynamic route and their exact descriptor ObjectIds. The catalog remains exactly 4 Schemas and 7 descriptors; builtin-only containers must have no descriptor.

This combined host extends the original protocol in `tests/DurableGraph.Tests/MetaBootstrapSchemaClosureGeneratorTests.cs` with the List protocol in `MetaBootstrapBuiltinListGeneratorTests.cs`, the Array protocol in `MetaBootstrapArrayGeneratorTests.cs` and the Dictionary protocol in `MetaBootstrapDictionaryGeneratorTests.cs`. It is not identical to those standalone fixtures: the original Root/container changes remain, so all nine rows advance by Delta. Each run creates a new store and four independent model histories; the second build verifies those accepted history bytes without changing them. Direct inspection of Dictionary Delta operation groups and NoChange remains source-test evidence. This package witness covers current V1 ScalarDefault/CurrentDefault maps, not the complete comparer, key or historical Upgrade matrix. A receipt for an earlier host does not qualify this expanded model or the new wire.

Run from the repository root after the production slice is frozen and source checks pass:

```powershell
./experiments/PackageConsumerProbe/Run-MetaBootstrapSchemaProbe.ps1 -StoragePackageSource <verified-six-package-feed>
# Or consume an existing ten-package feed without repacking:
./experiments/PackageConsumerProbe/Run-MetaBootstrapSchemaProbe.ps1 -StoragePackageSource <verified-six-package-feed> -PackageSource <ten-package-feed> -Version <G>
```

The runner copies the consumer to a fresh external work directory, isolates MSBuild/central-package boundaries and NuGet cache/config, checks actual package versions and loaded DLL hashes, and preserves source hashes, assets, history hashes, process evidence and `result.json`. `-WorkDirectory` must name a nonexistent directory. Each lane is a normal process that closes all resources; this is not ProcessCrashOnly qualification. No ProjectReference, manual analyzer, workspace source inclusion, fault injection or network publishing is used.
